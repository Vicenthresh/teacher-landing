# Phase 0 — the design gate

**Date:** 2026-11-17 · **Scope:** style only, no real content · **Status:** waiting for review

Phase 0 built every ingredient from the vault inventory (hub §4) into `/styleguide`,
rendered it in two skins, and measured it. Nothing from Phase 1 onward was started:
no taskbar on `/`, no content collections, no EN pages, no deploy, no remote.

## The two plates

Same markup, same classes. `data-skin="aero"` and `data-skin="y2k"` only change
tokens. A segmented control in §02 flips the whole isolated audit between skins,
which is the fastest way to catch a component that hard-codes a colour.

- **Aero base (proposed):** sky, glass, gloss, near-white windows, soft radii.
- **Y2K navy:** navy plate, hard chrome, 2 px radii, bevels, cyan/lime neon,
  scanlines.

## Measurements

Generated with `pnpm build && node scripts/contrast.mjs && node scripts/weight.mjs`.
Numbers are also rendered in `/styleguide` §03 from the JSON.

| Item | Result | Budget |
|---|---|---|
| `/` HTML+CSS+JS, gzip | **10.4 KB** | ≤ 100 KB |
| `/styleguide/` HTML+CSS+JS, gzip | **20.0 KB** | ≤ 100 KB |
| Fonts (Silkscreen 400 + 700, Latin) | **15.6 KB** | ≤ 25 KB |
| Cursors (3 × 32 px PNG) | **3.0 KB** | ≤ 6 KB |
| Worst first load (`/styleguide/`) | **38.6 KB gzip** | ≤ 350 KB |
| Lighthouse `/` | 99 / 100 / 100 / 100 | ≥ 95 / 100 |
| Lighthouse `/styleguide/` | 99 / 100 / 100 / 100 | ≥ 95 / 100 |
| LCP, Lighthouse mobile (4G sim, CPU 4×) | 0.8 s / 0.9 s | < 2.5 s |
| CLS | 0 | — |
| Contrast pairs passing AA | **26 / 26** | all |

Contrast is computed against composited pixels, not token hex: glass over sky and
over grass, tray over sky, worst stop of each gradient. Run `node scripts/contrast.mjs`
to re-check; it exits 1 on a failure.

Chrome headings are the one deliberate compromise: the silver face is decorative
and the measured pair is the face itself (dark metal on Aero, silver on navy),
not the 1 px stroke. Without that, gradient text would be unmeasurable.

## Verdict

**Ratio: Aero 75 / Y2K 25.** Aero carries the site; Y2K supplies the bite and the
one dark section. Full Y2K reads as a joke site and buries the teaching content;
full Aero has no edge.

- **Keep:** window chrome, glossy buttons, sky/grass plate, pixel font (short
  headings only), taskbar + start menu, ticker, bubbles, sounds off by default.
- **Conditional:** glass panel (one per viewport, `@supports` fallback), chrome
  heading (≥ 1.6 rem, stroke/face contrast), draggable windows (desktop extra,
  nothing depends on position), boot screen (once per session, skippable),
  cursors (candidate to drop: 3 requests for a detail nobody notices).
- **Drop:** visitor counter (an invented number is fake social proof; a static
  site has no honest source), any wallpaper image.

## Blocked, not guessed

1. **Name and domain** — hero, `<title>`, OG, email.
2. **Mood ratio** — recommendation above; the decision is the owner's.
3. **One page or five** — proposed: one page with anchored windows.
4. **Prices public?** — proposed: public packages in CLP; no amount was invented.

## Known gaps / next

- Mobile nav lives only in the Start menu below 540 px. It works and is
  keyboard-accessible, but Phase 1 should test if it is discoverable enough.
- `backdrop-filter` is still untested on a real mid-range Android. The fallback
  exists; the device test is Phase 3.
- The styleguide is 13.6k px tall on purpose (every ingredient at once). Its TBT
  varies 0–245 ms on a 4× throttled CPU because of the plate animations and DOM
  size; `/` is the page that ships.
- Screenshots are attached to the thread, not committed (weight).

## Reproduce

```sh
pnpm install
pnpm dev                 # http://localhost:4321/styleguide/
pnpm build               # astro check && astro build
pnpm measure:contrast    # writes src/data/contrast.json, exits 1 on failure
pnpm measure:weight      # writes src/data/weight.json from dist/
pnpm preview             # production build for Lighthouse
```
